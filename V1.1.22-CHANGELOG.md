# Changelog — v1.1.22

Everything below is relative to v1.1.21. Work in progress. Not yet tested in a live session unless marked.

Changes are dated (YYYY-MM-DD) from this point on. Entries without a date were made before dating started.

---

## Grid overlay (new)

- **`overlays/grid-overlay.html`** — an OBS overlay that places the items and dungeon prizes on a grid the user sets. It reads the tracker's Items API and is fully separate from the tracker window.
- **Grid size** 2×2 up to 20×20. Items are placed by Arrange; Export / Import / Reset in the settings.
- **Look:** item fill (colours, gradient, effects: falling, fade, edges, pulse). The pulse plays once, not on repeat.
- **Dungeons** have a box around them. Optional dungeon counts (text) can be shown; their layout is to be adjusted later.
- **Medallions** show MM / TR / BOTH drawn on the medallion picture, from the tracker's state. No separate square.
- **GO** is a filled circle, as in the item tracker. **Boomerang** is split blue / red, as in the item tracker.
- **Stats:** CHECKS, BONKS, DEATHS, REVIVALS and FLUTES, styled like the View-2 tracker boxes.
- **Add / remove** items in the layout.

## Items API — stats

- **`GET /stats`** returns the check, death, bonk, revival and flute counts (`main.js`, `apiStatState`). Needs a restart of the tracker app to load.
- **The tallies reach the API when they change.** A MutationObserver on the counters pushes an item snapshot (`js/items.js`, items.js build 1136k). Before this, a tally change without an item change never reached the overlay.

## Item sounds — map replay fixed

- **A collected map no longer replays over and over.** Two snapshot builders disagree: the slim one after each SRAM read leaves out the map and compass flags, so the sound code saw a map "picked up" on every other snapshot. `js/item-sounds.js` now keeps the last known value for each key and merges snapshots, so a key missing from one builder keeps its value. The 2-second cooldown on other sounds is unchanged.
- Verified with a simulation of alternating snapshots (plays once). Not yet checked in a live run.

## Item tracker

- **Item count verified** (2026-11-16). Three live runs on 1154k+ with the debug log, standard and MC: no dips, and every finished dungeon at its full count. Closed.
- **Boss-key dip held** (2026-11-15, items.js 1154k). A key that arrives with no chest is almost always the boss's: picked up after the kill, while the boss flag lands about 15 s later, after the prize. The count dipped by one for that time (MM: 1/2 → 0/2 → 1/2). The shown count now holds until a location lands or 30 s pass, then the fresh count stands. A key within 1.5 s of a chest still applies at once. Display only: the count can't stay wrong. Replay of the 2026-11-15 log: the MM and DP dips are gone; TR's late chest key still shows one high for about a second before correcting.
- **Key subtraction back to the earlier rule** (2026-11-14, items.js 1152k). Every small key held is subtracted again, whenever it arrived, capped at the dungeon's chest-key count. The chest-key credit (1144k–1151k) depended on game timing that varies (torch key 2–4 s before its flag, boss key 16–19 s), and each missed gap overcounted: DP showed 4/4 with the boss left. Kept: the room/inventory read pairing (1143k) and the high-water skip on key change (1141k). The pot/enemy-key cost this was thought to carry turned out not to exist (see 1154k).
- **[Reverted in 1154k] Drop keys logged** (2026-11-14, 1153k). The log showed the game's key counter (`$7EF4E0`) never counts vanilla pot or enemy keys in standard seeds (DP: all 3 pot keys collected, counter stayed at the 1 chest key), and their flags aren't set. Pot and enemy keys can't affect the count, so the extra read went back to key-drop and pottery modes only.
- **Room and key reads are paired** (2026-11-10, items.js 1143k). The inventory read (keys, map, compass, big key) is processed together with the room read it arrives with, so a key tick no longer dips the count for one read. Verified on IP and ToH replays. The chest-key credit added alongside it (1144k–1146k) was reverted in 1152k; see above.
- **[Reverted in 1152k] Late chest key no longer overcounts** (2026-11-13, items.js 1149k). A chest key can reach the tracker one read after its chest. It was never credited, so POD showed 5/5 with 4 items found until the boss. A key that lands within 1.5 seconds (about one read) of an unmatched chest is now credited to that chest. Kept short so a pot or enemy key picked up near a chest (Misery Mire) isn't taken for a chest key. Replaying the 2026-11-13 logs: POD credits 6 keys (was 5), the Ice Palace drop key is still not credited, nothing else changes. Re-entries in SW, TT, MM and IP held with no dips.
- **[Reverted in 1152k] Floor-item keys no longer overcount** (2026-11-14, items.js 1150k). At the DP torch, the ToH basement floor item and the GT torch the key counter ticks before the location bit (DP torch: 2.0 s apart). The key was never credited, so DP read one high from the torch on. When one of these floor-item bits rises, a key that arrived up to 2.5 s before it is credited to it. Only these three locations look back for a key; every other chest keeps the 1.5 s rule. Replay of the three 1146k+ logs: DP credits its torch key, POD as before, nothing else changes.
- **[Reverted in 1152k] Boss keys no longer count as items** (2026-11-14, items.js 1151k). The key from a boss is picked up after the kill, but the boss flag lands only after the prize (TT, MC boss shuffle: 19 s later). The key was never credited, so TT read 4 instead of 3. When a boss bit rises, a key that arrived up to 30 s before it is credited, as long as no chest opened in between. Replay of all five 1146k+ logs: TT credits its boss key, and the IP and MM keys earlier read as pot or enemy keys (16–19 s before their bosses) are credited as boss keys too. Those counts had been hidden by the maxItems cap.
- **Debug log** (2026-11-10, removed 2026-11-16 in items.js 1157k). Wrote one line per dungeon state change to `Documents/ALTTPR-Tracker-debug.log` while the item count was being verified. The `debug-log` IPC in `main.js` and `debugLog` in `preload.js` are gone too.

- **Ice Palace and Swamp Palace overcount fixed** (2026-11-04, items.js build 1141k). A small key picked up from a chest was counted as an item, so the count could show 3/3 with a chest still left. The key subtraction now uses the current key count, and the high-water mark no longer holds a count from before a key change. Verified on an Ice Palace replay: the count stayed correct through the keys, the compass and the boss. Other dungeons and the same lag on compass, map and big key are not yet checked.
- **Green dot on the dungeon Link is in is no longer shown on HC or CT** (items.js build 1137k).
- **Y item box** (earlier in v1.1.22): the item equipped to Y is boxed in the item tracker. Off by default (changed 2026-11-17); Settings toggle. Its colour can be changed with a picker beside the setting (2026-11-16, gold by default).
- **Current dungeon label** (2026-11-16, replaces the dungeon dot). The label of the dungeon Link is in ("POD", "SP"…) takes a colour, green by default, chosen with a picker beside the setting (Settings → Item Tracker → Highlights). Off by default (changed 2026-11-17), always off in race mode; HC and CT are left out. Keeps the dot's on/off setting. items.js 1155k, item-settings.js v6.
- **Goal moved to the map** (2026-11-16). It was in the bottom bar, where it crowded view 1 and pushed New Game off the edge; it now shows on the map's toolbar (see Map). The item tracker's title is back to `ALTTP Item Tracker`.
- **Bottom bar fits narrow windows** (2026-11-16, `items.css`). The connection status stays on one line ("Connected" wrapped in view 1). Below 420 px, Settings and Broadcast show their icons only; hover still names them.
- **Images:** fire rod and ice rod art rotated 45°; bottle images updated (blue "B", red "R", green "G", fairy bottle "F").

## Launcher — Goal

- **Goal dropdown** in the Other Settings popup, with the eight goals: Defeat Ganon (default), Master Sword Pedestal, All Dungeons, Triforce Hunt, Trinity, Crystals, Ganonhunt, Completionist. Saved as `alttp-goal`.
- **Other Settings popup fits the Goal list** (2026-11-16). "Master Sword Pedestal" ran 24 px past the popup's edge. The popup is now at least as wide as its button and widens to fit its rows; it floats over the next column.
- **Presets set the goal** (2026-11-05). Cabookey, Cabookeydrop, AD Enemizer, AD Keysanity and AD Keydrop Shop set All Dungeons. The other built-in presets set Defeat Ganon. Goals taken from the reference tracker's source; Open Standard matched by name to its `open` preset.
